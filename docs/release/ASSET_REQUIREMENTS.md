# 스토어 에셋 요구사항

- 문서 상태: `DRAFT`
- 브랜드 원본·승인·최종 캡처: `BLOCKED_EXTERNAL`
- 공식 요구사항 확인일: `2026-07-27`
- 적용 로케일: 우선 `ko-KR`, 추가 로케일은 별도 승인

현재 저장소에는 스토어 제출용으로 승인된 아이콘, 기능 그래픽, 최종 스크린샷 세트가 없다. 네이티브 기본 런처·스플래시 리소스는 제출용 브랜드 승인을 받은 에셋으로 간주하지 않는다.

## 1. Apple App Store

### 앱 아이콘

| 항목 | 요구사항 | 상태 |
|---|---|---|
| App Store 아이콘 원본 | 1024×1024 정사각형 | `BLOCKED_EXTERNAL` |
| 모양 | 원본은 정사각형, 시스템이 마스크를 적용하므로 모서리를 임의로 둥글게 자르지 않음 | `DRAFT` |
| 투명도 | 투명 배경 없이 최종 배경을 포함 | `DRAFT` |
| 콘텐츠 | 승인된 브랜드만 사용, 작은 글자·사진·스크린샷을 아이콘에 넣지 않음 | `BLOCKED_EXTERNAL` |
| 앱 내 일치 | 바이너리의 App Icon과 스토어 표시가 같은 브랜드 버전 | `BLOCKED_EXTERNAL` |

Expo 앱 구성의 `icon` 및 iOS 아이콘 설정이 승인 원본을 참조하는지 빌드 산출물에서 확인한다.

### 스크린샷

| 항목 | 요구사항 |
|---|---|
| 수량 | 디바이스 크기별 1~10장 |
| 형식 | `.jpeg`, `.jpg`, `.png` |
| 투명도 | 알파 채널 없음 |
| iPhone 6.9형 세로 | 1260×2736, 1290×2796 또는 1320×2868 |
| iPhone 6.9형 가로 | 위 규격의 가로·세로 반전 |
| iPad 13형 세로 | 2064×2752 또는 2048×2732 |
| iPad 13형 가로 | 위 규격의 가로·세로 반전 |

iPad 지원 여부와 제출 시점의 App Store Connect 슬롯은 실제 빌드의 지원 기기와 콘솔에 따라 달라진다. 위 대표 규격만으로 자동 축소가 허용되는지 콘솔에서 확인하고, 콘솔이 요구하는 추가 크기가 있으면 생성한다.

### 선택 에셋

- App Preview 비디오는 선택 사항이다. 사용한다면 App Store Connect의 디바이스별 비디오 규격, 길이, 형식, 수량을 제작 시점에 다시 확인한다.
- In-App Event, Custom Product Page, Game Center 등 현재 범위 밖 기능의 에셋은 기능을 실제로 도입할 때 별도 문서화한다.

## 2. Google Play

### 필수 그래픽

| 에셋 | 요구사항 | 상태 |
|---|---|---|
| Play 앱 아이콘 | 512×512, 32비트 PNG(알파 지원), 최대 1,024KB | `BLOCKED_EXTERNAL` |
| 기능 그래픽 | 1024×500, JPEG 또는 24비트 PNG(알파 없음) | `BLOCKED_EXTERNAL` |
| 휴대전화 스크린샷 | 최소 2장, 최대 8장 | `BLOCKED_EXTERNAL` |

### 스크린샷 파일 규격

- JPEG 또는 24비트 PNG이며 알파 채널을 사용하지 않는다.
- 각 변은 320~3,840px 범위여야 한다.
- 긴 변은 짧은 변의 두 배를 넘지 않는다.
- 앱의 추천 노출 품질을 위해 휴대전화 스크린샷은 최소 4장, 세로 1080×1920(9:16) 이상을 목표로 한다.
- 태블릿, Chromebook, Android TV, Wear OS를 지원한다고 선언하면 각 폼팩터의 필수 에셋과 스크린샷을 별도로 준비한다.

### 선택 에셋

- 미리보기 동영상은 YouTube URL로 등록하며 공개 또는 일부 공개로 제공한다. 연령 제한, 광고, 지역 제한, 심사 불가 콘텐츠가 없는지 확인한다.
- TV 배너, 360도 스테레오 이미지 등은 해당 기능·폼팩터를 실제 지원할 때만 준비한다.

## 3. 공통 캡처 계획

권장 순서는 핵심 가치를 먼저 보여 주며, Apple은 최대 10장, Google 휴대전화는 최대 8장 범위에서 최종 선정한다.

| 순서 | 화면 | 보여 줄 내용 | 캡션 초안 | 준비 상태 |
|---:|---|---|---|---|
| 1 | 홈 | 중요 공지와 주요 일정 | `중요한 소식을 한눈에` | `DRAFT` |
| 2 | 공지 | 고정 공지와 상세 | `놓치면 안 될 공지 확인` | `DRAFT` |
| 3 | 일정 | 목록·캘린더 전환 | `다가오는 일정을 편리하게` | `DRAFT` |
| 4 | 커뮤니티 | 게시판 목록과 글 | `구성원과 정보 공유` | `DRAFT` |
| 5 | 게시글 상세 | 댓글·답글·공감 | `게시글과 댓글로 소통` | `DRAFT` |
| 6 | 검색·북마크 | 콘텐츠 찾기와 저장 | `필요한 정보를 찾고 저장` | `DRAFT` |
| 7 | 알림 | 알림 목록과 설정 | `새 소식을 원하는 방식으로` | `DRAFT` |
| 8 | 설정 | 프로필·개인정보·계정 삭제 진입점 | `내 정보와 계정을 직접 관리` | `DRAFT` |

실제 구현되지 않았거나 출시 후보에서 비활성화된 화면은 캡처하지 않는다. 계정 삭제 화면은 local hard-delete 구현과 일치하지만, 공개 privacy/retention 문구가 법무 승인된 뒤에만 최종 스토어 에셋으로 확정한다.

## 4. 캡처 및 편집 규칙

- 출시 후보와 같은 커밋·버전의 실기기 또는 공식 시뮬레이터에서 캡처한다.
- 운영자의 실명, 이메일, 전화번호, 토큰, 학교 ID, 개인 사진을 사용하지 않는다.
- 심사용 테스트 계정과 별개인 가상 데이터 세트를 사용한다.
- 댓글·게시글·검색어에는 욕설, 개인정보, 저작권 미확인 자료를 넣지 않는다.
- 상태 표시줄의 시간, 통신사, 배터리 표시는 한 세트에서 일관되게 유지한다.
- 기기 프레임과 장식은 실제 UI를 가리거나 기기 기능처럼 오인하게 만들지 않는다.
- 텍스트와 UI를 늘이거나 합성해 실제 기능과 다른 인상을 주지 않는다.
- Apple/Google 배지, 경쟁사 상표, 가격·순위·수상 이력은 권리와 사실을 확인하지 않으면 넣지 않는다.
- 현지화된 캡션은 화면 속 언어와 일치시키고 잘림을 확인한다.
- 생성형 이미지나 스톡 이미지를 쓰면 상업적 이용 권리와 브랜드 허용 범위를 기록한다.

## 5. 작업 산출물 명명

승인된 원본은 저장소에 추가하기 전 보안·라이선스 검토를 거친다. 추천 파일명은 다음과 같다.

```text
icon/app-icon-master-1024.png
google/feature-graphic-ko-KR-1024x500.png
apple/iphone-6.9/01-home-ko-KR-1320x2868.png
apple/ipad-13/01-home-ko-KR-2064x2752.png
google/phone/01-home-ko-KR-1080x1920.png
```

각 내보내기에는 다음 메타데이터를 별도 기록한다.

- 원본 소유자와 승인자
- 라이선스 또는 내부 제작 근거
- 승인일과 브랜드 버전
- 캡처한 앱 버전, 빌드 번호, 커밋 SHA
- 로케일, 기기 규격, 파일 해시

## 6. 에셋 수용 체크리스트

- [ ] 앱 이름, 아이콘, 색상, 로고의 사용 승인이 있다.
- [ ] Apple 1024×1024 아이콘과 Google 512×512 아이콘을 각각 검증했다.
- [ ] Google 1024×500 기능 그래픽을 준비했다.
- [ ] 각 파일의 픽셀 크기, 색상 모드, 알파 채널, 파일 용량을 검사했다.
- [ ] Apple이 요구하는 지원 기기별 스크린샷 슬롯을 채웠다.
- [ ] Google 휴대전화 스크린샷 2~8장을 채우고 추천 품질을 확인했다.
- [ ] 지원한다고 선언한 태블릿·TV·Wear OS용 에셋을 모두 준비했다.
- [ ] 모든 이미지가 출시 후보 빌드와 일치한다.
- [ ] 개인정보와 비밀값이 이미지에 없다.
- [ ] 허위 기능, 임시 데이터 오류, 개발자 메뉴, 로컬 호스트가 보이지 않는다.
- [ ] ko-KR 문구가 `STORE_LISTING_KO.md`의 승인본과 일치한다.
- [ ] 실제 App Store Connect와 Play Console 업로드 검증을 통과했다.
