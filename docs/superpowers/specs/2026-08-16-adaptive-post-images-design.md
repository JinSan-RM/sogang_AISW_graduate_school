# Adaptive Post Detail Images Design

## Goal

공지사항과 참여활동 상세 이미지가 원본 방향과 비율에 맞는 높이를 사용하도록 변경한다. 가로 사진과 일반적인 세로 사진은 사용 가능한 가로폭과 원본 비율을 사용하고, 계산된 높이가 `500px`를 넘는 긴 사진은 제한된 미리보기와 인앱 전체보기를 제공한다.

이 결정은 `2026-08-10-notice-image-contain-design.md`의 공지 이미지 `230px` 고정 프레임 결정을 대체한다.

## Approved behavior

- 이미지 너비는 해당 상세 화면에서 사용할 수 있는 너비의 `100%`다.
- 이미지가 로드되면 원본 `width / height`를 화면의 `aspectRatio`로 사용한다.
- 계산된 자연 높이가 `500px` 이하인 사진은 가로·세로 방향과 관계없이 원본 비율 전체를 표시한다.
- 계산된 자연 높이가 `500px`를 초과하면 상세 화면의 미리보기 높이를 정확히 `500px`로 제한한다.
- 긴 이미지 미리보기는 가로폭을 채운 원본 비율 이미지를 상단 기준으로 보여주고, 넘치는 아래 영역만 프레임 밖으로 숨긴다. 이미지 좌우에 내부 여백을 만들지 않는다.
- 긴 이미지 미리보기 하단에는 흰색으로 이어지는 오버레이와 `사진 전체보기` 버튼을 표시한다.
- `사진 전체보기`를 누르면 현재 이미지를 인앱 전체화면으로 열며, 화면 가로폭과 원본 비율을 사용해 세로 스크롤로 이미지 전체를 볼 수 있다.
- 전체화면에는 닫기 또는 뒤로가기 컨트롤을 제공하고, Android 하드웨어 뒤로가기도 전체화면만 닫는다.
- 이미지 크기를 아직 알 수 없거나 판독할 수 없을 때만 `16 / 9` 비율을 임시 대체값으로 사용한다.
- 이미지가 바뀌면 새 이미지의 원본 크기로 비율을 다시 계산한다.
- 갤러리에서는 현재 선택된 이미지가 `500px` 기준을 넘을 때만 전체보기 버튼을 표시하고 전체화면에도 현재 이미지를 연다.
- 보호 미디어 URL 처리, 갤러리 이동 버튼과 장수 표시는 기존 동작을 유지한다.

## Scope

다음 게시글 상세 이미지에 적용한다.

- `board_type === "notice"`인 공지사항의 이미지 첨부 전체
- `club-promo`와 `networking-programs` 참여 안내의 대표 이미지
- `board_type === "activity_certification"`인 동아리·스터디 등 활동 인증 이미지 갤러리

행사 사진첩, 원우회 활동내역, 상조회 증빙, 일반 커뮤니티 첨부 등 범위 밖 화면의 이미지 정책은 변경하지 않는다.

## Component design

기존 `NaturalAspectMediaImage`의 원본 크기 판독 흐름을 재사용하는 상세 전용 확장 이미지 컴포넌트를 둔다. 이 컴포넌트는 이미지 원본 크기와 실제 컨테이너 너비로 자연 높이를 계산하고 `500px` 기준에 따라 일반 이미지 또는 접힌 미리보기를 렌더링한다.

공지사항은 기존의 `MediaImage resizeMode="contain"`과 `230px` 전용 프레임을 제거하고 확장 이미지 컴포넌트로 통일한다. 참여 안내와 활동 인증의 대표 이미지 영역도 같은 컴포넌트를 사용한다. 여러 장을 넘길 때는 현재 첨부 ID를 기준으로 이미지 컴포넌트를 새로 구성하여 이전 이미지의 비율과 전체보기 상태가 남지 않게 한다.

이미지 주변의 기존 모서리, 화면 여백, 갤러리 화살표와 카운터는 유지한다. `500px` 기준값은 상세 이미지 컴포넌트의 단일 상수로 정의해 후속 디자인 조정 시 한 곳만 수정한다.

## Data flow and failure behavior

1. 상세 API 응답에서 이미지 첨부를 선택한다.
2. 미디어 URL을 기존 `MediaImage` 흐름으로 해석하고 이미지를 로드한다.
3. 로드 이벤트의 유효한 원본 크기로 `aspectRatio`를 갱신한다.
4. 컨테이너 너비와 원본 비율로 자연 높이를 계산하고 `500px` 초과 여부를 판단한다.
5. 기준 이하이면 자연 높이를 사용하고, 기준 초과이면 높이 `500px` 미리보기와 전체보기 버튼을 사용한다.
6. 전체보기 버튼을 누르면 현재 이미지의 인앱 전체화면을 열고, 닫으면 같은 상세 위치로 돌아간다.
7. 유효한 크기가 없으면 임시 `16 / 9` 비율을 유지하며 전체보기 버튼을 표시하지 않는다.
8. 갤러리에서 다른 이미지를 선택하면 선택한 이미지 기준으로 같은 과정을 다시 수행한다.

미디어 접근 실패와 첨부 클릭 오류 안내는 기존 처리 방식을 유지한다. 이미지 비율 계산 실패가 상세 화면 전체의 오류로 이어지지 않게 한다.

## Alternatives considered

1. **자연 높이 + 500px 초과 시 전체보기 — 선택.** 일반 이미지는 그대로 보여주고 긴 이미지만 시안처럼 접어 상세 본문이 지나치게 밀리지 않게 한다.
2. 모든 이미지를 원본 비율로 무제한 표시. 잘림은 없지만 매우 긴 이미지가 상세 본문을 과도하게 밀고 전체보기 진입점을 제공하지 못한다.
3. 세로 방향만 고정 프레임 사용. 구현은 단순하지만 화면 너비와 실제 원본 비율에 따라 긴 이미지 판정이 달라지는 요구를 정확히 반영하지 못한다.

## Testing and verification

- 이미지 크기 추출 유틸리티가 유효한 가로·세로 크기를 올바른 비율로 전달하는지 단위 테스트한다.
- 컨테이너 너비와 원본 크기로 계산된 자연 높이가 `500px` 이하·초과·정확히 같은 경계에서 올바른 미리보기 정책을 선택하는지 단위 테스트한다.
- 공지 이미지가 고정 `230px`/`contain` 분기를 사용하지 않고 자연 비율 렌더러를 사용하는지 회귀 테스트한다.
- 참여 안내와 활동 인증 대표 이미지가 고정 높이 대신 자연 비율 렌더러를 사용하는지 회귀 테스트한다.
- 갤러리 이미지 변경 시 현재 이미지가 별도 키로 렌더링되는지 확인한다.
- 긴 이미지에만 `사진 전체보기` 버튼이 나타나고, 버튼으로 현재 이미지의 전체화면을 열고 닫을 수 있는지 확인한다.
- 프론트엔드 테스트, 타입체크, 린트와 웹 빌드를 실행한다.
- 실행 화면에서 일반 가로·세로 이미지는 내부 여백과 잘림이 없고, `500px`를 넘는 이미지는 제한된 미리보기와 전체보기 화면에서 각각 의도대로 표시되는지 캡처로 검증한다.
