# 원우회비 납부자 명부 설계

## 목표

참여활동의 참가자 등록 기준을 앱 회원 계정에서 완전히 분리된 원우회비 납부자 명부로 전환한다. 관리자는 관리자 페이지의 `원우회비` 탭에서 현재 명부를 엑셀로 일괄 등록하고 검색할 수 있으며, 회원은 활동 인증 작성 시 이 명부에 있는 사람만 참가자로 선택할 수 있다.

## 범위와 결정 사항

- 기간이나 학기 구분 없이 하나의 현재 원우회비 납부자 명부만 관리한다.
- 명부는 앱 회원 계정과 연결하지 않는다. 가입하지 않은 납부자도 명부와 참가자 검색에 포함된다.
- 명부의 필수 필드는 이름, 전공, 학번이다.
- 학번이 명부의 고유 식별값이며 형식은 대문자 `A`와 숫자 5자리인 `^A\d{5}$`이다.
- 관리자 엑셀 업로드는 학번 기준 upsert로 동작한다. 신규 학번은 추가하고 기존 학번은 이름과 전공을 덮어쓴다.
- 검색은 이름과 학번의 부분 일치를 지원한다.
- 검색 결과 표기는 `/`를 사용하지 않고 `이름 전공 학번` 순서로 공백을 사용한다.
- 원우회비 명부 검색은 관리자 탭에만 한정하지 않는다. 지원금을 받기 위해 작성하는 참여활동의 활동 인증 화면에 있는 `참가자` 검색과 선택까지 이번 범위에 포함한다.
- 첨부된 기준 파일은 헤더가 없는 세 열 `이름`, `전공`, `학번`으로 읽는다. 셀 안의 공백으로 열을 나누지 않는다. `보안 및 블록체인`처럼 전공명 자체에 공백이 있을 수 있기 때문이다.
- 원본 엑셀과 납부자 개인정보를 시드 데이터, 마이그레이션 또는 Git 커밋에 포함하지 않는다.

## 선택한 구조

### 별도 납부자 모델

새 `dues_payers` 테이블을 만든다.

| 필드 | 타입 | 규칙 |
| --- | --- | --- |
| `id` | integer | 기본 키 |
| `student_number` | varchar(20) | 필수, 고유, 인덱스, `^A\d{5}$` |
| `name` | varchar(50) | 필수, 검색 인덱스 |
| `major` | varchar(100) | 필수 |
| `created_at` | datetime | 필수 |
| `updated_at` | datetime | 필수 |

`users.dues_status`는 더 이상 참가자 자격이나 원우회비 관리에 사용하지 않는다. 회원 관리 UI와 일반적인 관리자 회원 수정 API에서 회비 상태 조작을 제거한다. 기존 DB 컬럼은 이번 변경에서 즉시 삭제하지 않고 레거시 호환용으로만 유지하며, 원우회비 도메인과 어떤 관계도 맺지 않는다.

### 대안과 기각 이유

1. 기존 회원의 `dues_status` 재사용: 학번이 없고 미가입 납부자를 표현할 수 없어 기각한다.
2. 업로드 때마다 전체 명부 교체: 누락된 행 하나로 기존 납부자가 사라질 수 있어 기각한다.
3. 별도 명부와 학번 기반 upsert: 회원 계정과 독립적이고 재업로드가 안전하므로 선택한다.

## API와 권한

원우회비 전용 라우터를 추가하고 모든 응답은 기존 `{status, data}` 형식을 유지한다.

### 활동 인증용 납부자 검색

`GET /api/dues-payers/search?q=<검색어>&size=8`

- 인증된 회원과 관리자만 호출할 수 있다.
- `q`는 1자 이상이며 이름 또는 학번을 부분 일치로 검색한다.
- 빈 검색어로 전체 명부를 내려주지 않는다.
- 응답 항목은 `id`, `name`, `major`, `student_number`이다.
- 정렬은 이름, 학번, ID 순으로 고정한다.

### 관리자 명부 조회

`GET /api/dues-payers/admin/payers?q=&page=1&size=50`

- 관리자만 호출할 수 있다.
- 이름 또는 학번 검색과 페이지네이션을 지원한다.
- 전체 학번을 포함한 명부 항목과 전체 건수를 반환한다.

### 관리자 엑셀 업로드

`POST /api/dues-payers/admin/import`

- 관리자만 호출할 수 있는 multipart `.xlsx` 업로드이다.
- 첫 번째 워크시트의 사용 범위를 읽고, 헤더 없는 세 열을 이름, 전공, 학번으로 해석한다.
- 각 값을 문자열로 변환한 뒤 앞뒤 공백을 제거하고 학번은 대문자로 정규화한다.
- 빈 행은 건너뛴다. 일부 셀만 채워진 행은 빈 값 오류로 처리한다.
- 이름, 전공, 학번 중 빈 값이 하나라도 있으면 전체 업로드를 거절한다.
- 학번 형식이 `^A\d{5}$`와 다르면 전체 업로드를 거절한다.
- 같은 파일 안에 중복 학번이 하나라도 있으면 값이 동일하더라도 전체 업로드를 거절한다.
- 검증이 모두 끝난 뒤 하나의 DB 트랜잭션에서 학번 기준 upsert를 수행한다. 검증 실패나 DB 실패 시 한 행도 반영하지 않는다.
- 성공 응답은 `created`, `updated`, `unchanged`, `total_rows` 건수를 반환한다.
- 실패 응답은 행 번호와 사유를 포함하되, 운영 로그에는 명단 전체나 엑셀 원문을 기록하지 않는다.
- 성공한 업로드는 관리자 감사 로그에 처리 건수만 기록한다.

### 관리자 전체 삭제

`POST /api/dues-payers/admin/delete-all`

- 관리자만 호출할 수 있다.
- 요청 본문은 정확히 `{ "confirmation": "진짜 삭제" }`여야 한다.
- 문구가 다르면 삭제하지 않고 확인 오류를 반환한다.
- 성공하면 `dues_payers`의 모든 행을 물리적으로 삭제하고 삭제 건수를 반환한다.
- 휴지통, 소프트 삭제, 자동 복원 기능은 제공하지 않는다. 복구하려면 관리자가 엑셀을 다시 업로드해야 한다.
- 감사 로그에는 삭제 건수만 남기고 납부자 개인정보는 남기지 않는다.

## 관리자 화면

기존 관리자 페이지 탭 목록에 `원우회비` 탭을 추가한다. 대형 `admin/index.tsx`에 로직을 더 쌓지 않도록 명부 화면과 업로드·삭제 상태는 별도 관리자 컴포넌트로 분리한다.

탭은 다음 기능을 제공한다.

- 현재 총 납부자 수
- 이름 또는 학번 검색
- 검색 결과에서 `이름 전공 학번` 공백 표기
- `.xlsx` 파일 선택과 업로드
- 업로드 성공 시 추가, 갱신, 변경 없음 건수 안내
- 서버가 반환한 행별 검증 오류 안내
- 명부 전체 영구 삭제

전체 삭제 확인은 다음 세 단계로 진행한다.

1. `명부 전체 삭제` 버튼을 누른다.
2. `삭제 후 복원할 수 없으며 엑셀로 재등록해야 합니다. 진짜 삭제할까요?` 경고에서 계속을 선택한다.
3. 입력란에 `진짜 삭제`를 정확히 입력해야 최종 삭제 버튼이 활성화된다.

최종 API도 같은 문구를 검증하므로 프런트엔드 확인 절차를 우회해 삭제할 수 없다.

## 지원금 활동 인증 참가자 흐름

- 지원금을 받기 위해 작성하는 참여활동의 활동 인증 생성·수정 화면에 있는 `참가자` 입력란을 원우회비 납부자 검색 API로 교체한다.
- 현재 동아리·스터디·네트워킹 활동 인증 게시판은 같은 활동 인증 작성·수정 화면과 `참가자` 입력란을 공유한다. 별도의 다른 참가자 검색 기능을 새로 만들거나 변경하는 범위가 아니다.
- 해당 입력란에서 현재 `GET /api/users/search`를 호출하는 로직은 `GET /api/dues-payers/search`를 호출하도록 변경한다. 회원 검색 API는 이 지원금 활동 인증의 참가자 등록에 사용하지 않는다.
- 이름이나 학번을 입력하면 납부자 명부만 검색한다.
- 결과와 선택 칩은 `/` 없이 `이름 전공 학번` 순서의 공백 표기를 사용한다.
- 작성자 본인도 자동 선택하지 않는다. 참가자라면 명부에서 직접 검색해 추가한다.
- 클라이언트는 선택된 납부자 ID 목록을 전송한다.
- 백엔드는 활동 인증 생성과 참가자 변경 시 모든 ID가 현재 명부에 존재하는지 검증한다.
- 백엔드는 검증된 명부에서 참가자 이름 스냅샷을 생성해 활동 글에 보존한다. 클라이언트가 임의로 보낸 이름은 신뢰하지 않는다.
- 명부 전체 삭제나 이름 변경 이후에도 이미 작성된 활동 기록의 참가자 이름 스냅샷은 유지한다.
- 기존 `participants`와 `participant_user_ids`를 가진 활동 기록은 계속 조회할 수 있다. 기존 기록에서 참가자를 변경할 때는 현재 원우회비 명부에서 다시 선택하도록 안내한다.
- 신규 활동 인증은 한 명 이상의 유효한 원우회비 납부자를 요구한다.
- 참여활동 탭의 참가자 안내 문구도 회원의 재학·회비 상태 설명을 제거하고, 원우회비 납부자 명부에 등록된 사람만 검색·선택할 수 있다고 안내한다.

## 오류 처리

- 파일 확장자나 워크북 파싱 실패: `INVALID_DUES_WORKBOOK`
- 필수 셀 빈 값: `DUES_IMPORT_EMPTY_VALUE`
- 잘못된 학번: `DUES_IMPORT_INVALID_STUDENT_NUMBER`
- 파일 내 중복 학번: `DUES_IMPORT_DUPLICATE_STUDENT_NUMBER`
- 존재하지 않는 참가자 ID: `INVALID_DUES_PAYER`
- 잘못된 삭제 확인 문구: `DUES_DELETE_CONFIRMATION_REQUIRED`

각 오류는 기존 오류 응답 `{status, message, code}`를 사용한다. 엑셀 검증 오류에는 사용자가 수정할 수 있도록 1부터 시작하는 원본 행 번호를 함께 제공한다.

## 테스트와 검증

### 백엔드

- Alembic 업그레이드가 `dues_payers` 테이블, 고유 제약, 검색 인덱스를 생성하는지 확인한다.
- 관리자만 명부 조회, 업로드, 전체 삭제를 호출할 수 있는지 확인한다.
- 기준 파일 형식의 283행과 같은 헤더 없는 3열 워크북이 등록되는지 확인한다.
- 첫 업로드는 추가, 같은 학번 재업로드는 이름·전공 갱신, 동일 값은 변경 없음으로 집계되는지 확인한다.
- 잘못된 학번, 부분 빈 행, 파일 내 중복 학번 각각에서 전체 트랜잭션이 롤백되는지 확인한다.
- 이름과 학번 검색이 미가입 납부자까지 반환하는지 확인한다.
- 삭제 문구가 틀리면 유지되고 정확한 문구에서만 전체 삭제되는지 확인한다.
- 활동 인증이 존재하지 않는 납부자 ID와 임의 참가자 이름을 거절하는지 확인한다.
- 명부 삭제 후에도 기존 활동의 참가자 이름 스냅샷이 유지되는지 확인한다.
- 기존 회원의 `dues_status`, `enrollment_status`, 활성 여부가 납부자 검색 결과에 영향을 주지 않는지 확인한다.

### 프런트엔드

- 관리자 탭에 `원우회비`가 노출되고 관리자 외 사용자는 기존 관리자 가드로 차단되는지 확인한다.
- 엑셀 선택과 업로드 결과 집계, 서버 검증 오류가 표시되는지 확인한다.
- 이름·학번 검색과 `이름 전공 학번` 공백 표기를 확인한다.
- 3단계 삭제 상태에서 정확한 문구 전에는 최종 버튼이 비활성인지 확인한다.
- 활동 인증 참가자 검색이 회원 API가 아닌 납부자 API를 호출하는지 확인한다.
- 지원금 활동 인증의 생성과 수정 화면에서 공유하는 `참가자` 입력란이 납부자 검색·선택 규칙을 사용하는지 확인한다.
- 선택된 납부자 ID가 활동 인증 요청에 포함되고 이름을 직접 입력할 수 없는지 확인한다.
- 프런트엔드 단위 테스트와 TypeScript typecheck를 통과한다.

### 통합 검증

- 백엔드 전체 테스트와 컴파일/import 검사를 실행한다.
- 프런트엔드 전체 단위 테스트와 typecheck를 실행한다.
- 로컬 Docker PostgreSQL에서 Alembic 업그레이드, 관리자 업로드, 회원 참가자 검색, 활동 인증 생성, 3단계 전체 삭제 순서의 smoke test를 수행한다.
