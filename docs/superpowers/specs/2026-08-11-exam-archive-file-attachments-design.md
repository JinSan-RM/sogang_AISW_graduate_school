# 시험족보 파일 첨부 설계

## 목표

시험족보 글쓰기에서 사진 보관함의 이미지와 서버가 이미 허용하는 일반 문서를 각각 명확한 진입점으로 첨부할 수 있게 한다.

## 승인 동작

- `exam-archive` 게시판 글쓰기의 첨부 영역에 `이미지 첨부`와 `파일 첨부` 버튼을 함께 표시한다.
- `이미지 첨부`는 기존 이미지 선택기를 열어 여러 이미지를 업로드한다.
- `파일 첨부`는 기존 문서 선택기를 열어 여러 파일을 업로드한다.
- 파일 선택기는 현재 서버 허용 정책을 그대로 따른다: PDF, PPT/PPTX, DOC/DOCX, XLS/XLSX, HWP와 허용 이미지 형식.
- 이미지는 썸네일로, 이미지가 아닌 파일은 원본 파일명 목록으로 표시하며 각각 삭제할 수 있다.
- 업로드 진행률과 기존 오류 안내 모달을 두 버튼이 공유한다.

## 구현 경계

- 변경 범위는 공통 작성 폼의 `exam-archive` 분기와 첨부 선택 핸들러로 제한한다.
- 다른 일반 게시판과 활동인증·사진첩·상조회·관리자 참여 게시글의 첨부 UI는 변경하지 않는다.
- 기존 `pickAndUploadImages`, `pickAndUploadDocuments`, 미디어 업로드 API, MIME/확장자 서버 검증을 재사용한다.
- 데이터 모델, API 요청 형식, DB 마이그레이션은 변경하지 않는다.

## 대안

1. **이미지와 파일 버튼 분리 — 선택.** 모바일에서 사진 보관함과 파일 앱의 역할이 분명하고 기존 이미지 경험도 보존한다.
2. 단일 `첨부` 버튼으로 문서 선택기만 사용. 구현은 단순하지만 모바일 사용자가 사진 보관함에서 이미지를 고르기 어렵다.
3. 모든 자료공유 게시판의 첨부 UI를 동시에 변경. 일관성은 높지만 이번 시험족보 요구보다 범위가 넓다.

## 오류 처리

- 선택 취소는 첨부 상태를 바꾸지 않는다.
- 업로드 실패는 기존 `업로드 실패` 안내를 사용하고 성공한 기존 첨부를 보존한다.
- 허용되지 않은 형식과 크기 초과는 서버 검증 결과를 기존 업로드 오류 흐름으로 표시한다.

## 검증

- 회귀 테스트에서 `exam-archive`만 두 선택 경로를 제공하는지 확인한다.
- 이미지 버튼이 이미지 선택기를, 파일 버튼이 문서 선택기를 호출하는 계약을 검증한다.
- 이미지 썸네일과 비이미지 파일명 목록이 함께 유지되는지 확인한다.
- 프론트엔드 전체 테스트, 타입 검사, 린트와 웹 export를 실행한다.
