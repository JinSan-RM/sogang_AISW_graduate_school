# 상세 뒤로가기 상태 복원 및 활동 인증 계좌 수정 설계

## 목적

게시글 상세에서 `<`를 눌렀을 때 특정 탭이나 게시판을 새로 여는 대신, 사용자가 상세에 진입하기 직전의 목록 상태로 돌아간다. 또한 기존 동아리·스터디 활동 인증 글에서도 저장된 계좌번호를 노출하지 않으면서 새 계좌번호로 변경할 수 있게 한다.

이번 수정은 사용자가 보고한 참여활동 이슈 140과 활동 인증 수정 이슈 143의 회귀 수정이다. 동아리·스터디뿐 아니라 공지사항, 커뮤니티 등 공통 게시글 상세의 뒤로가기에도 같은 원칙을 적용한다.

## 확인된 원인

### 상세 뒤로가기

현재 상세 화면은 일부 게시판에서 탐색 기록이 있어도 `router.replace(...)`로 상위 경로를 새로 연다. 활동 인증에는 `/board/{boardId}`로 강제 이동하는 별도 예외도 있다. 이 과정에서 상세 진입 전 화면 인스턴스가 복원되지 않아 선택했던 상위 탭, 하위 탭, 필터, 검색어, 정렬 및 스크롤 위치가 사라진다.

참여활동 탭 루트는 별도 상태 없이 열리면 동아리 안내 게시판으로 초기화되므로, 스터디 활동 인증에서 돌아왔는데 다른 참여활동 상태가 보이는 현상도 발생할 수 있다.

### 계좌번호 수정

`metadata.bank_account`는 민감정보이므로 일반 회원의 게시글 목록·상세 응답에서 제거된다. 백엔드는 수정 요청에서 이 키가 생략되면 저장된 계좌번호를 유지하고, 키가 명시되면 새 값으로 교체하는 계약을 이미 제공한다.

프론트엔드는 상세 응답에 `bank_account`가 없다는 이유로 기존 글의 계좌 입력을 `readonly` 처리한다. 따라서 백엔드는 안전한 교체를 지원하지만 사용자가 새 값을 입력할 수 없다.

## 검토한 접근

### 1. 실제 탐색 기록으로 복귀하고 직접 진입만 명시적 경로로 대체 — 채택

상세 진입 전 화면이 스택에 있으면 `router.back()`을 사용한다. 이 방식은 별도 상태 복제 없이 실제 목록 화면 인스턴스를 복원하므로 탭, 필터, 검색어, 정렬 및 스크롤 위치를 가장 정확하게 유지한다.

외부 링크, 새로고침 또는 알림 직접 진입처럼 이전 화면이 없을 때만 `fromBoardId`의 게시판 목록이나 제품 IA의 상위 탭으로 `replace`한다.

### 2. 상세마다 탭·필터·스크롤을 URL 파라미터로 복제 — 미채택

직접 링크에서도 일부 상태를 재구성할 수 있지만 모든 목록 상태를 중복 직렬화해야 하고, 화면별 파라미터 누락으로 같은 문제가 반복될 가능성이 높다.

### 3. 전역 스토어에 모든 목록 상태 저장 — 미채택

복원 범위는 넓지만 화면 수명과 무관한 상태가 남고 초기화 규칙이 복잡해진다. 정상적인 스택 복귀로 해결 가능한 문제에 비해 과도하다.

## 확정 동작

### 공통 상세 뒤로가기

1. 상세 화면을 앱 내부 목록에서 열었고 `router.canGoBack()`이 참이면 게시판 종류와 무관하게 `router.back()`을 실행한다.
2. 이전 화면이 없고 유효한 `fromBoardId`가 있으면 `/board/{fromBoardId}`로 교체한다.
3. 두 조건 모두 없으면 게시판의 제품 상위 경로로 교체한다.
   - 공지 → 공지사항 탭
   - 자료·행사 사진첩 → 커뮤니티 탭
   - 동아리·스터디·네트워킹 → 참여활동 탭
   - 그 외 → 기존 `boardParentRoute` 규칙
4. 화면의 `<`와 Android 하드웨어 뒤로가기는 동일한 결정 함수를 사용한다.
5. 활동 인증만 `/board/{post.board_id}`로 강제 이동하던 예외는 제거한다.

정상 진입에서는 실제 이전 화면을 복원하므로 동아리·스터디의 안내/모집/활동 인증 선택, 공지 필터, 검색어, 정렬 및 스크롤 위치를 별도로 복사하지 않는다.

### 활동 인증 계좌번호 수정

1. 새 활동 인증 작성에서는 계좌번호를 기존과 같이 필수 입력한다.
2. 기존 활동 인증 수정에서는 계좌 입력란을 항상 활성화하고 기존 값은 채우지 않는다.
3. 수정 화면 안내는 `기존 계좌는 표시되지 않아요. 변경할 경우 새 계좌를 입력해주세요.` 취지로 표시한다.
4. 수정 시 계좌 입력을 비워 두면 요청 metadata에서 `bank_account`를 생략하여 백엔드가 기존 값을 유지한다.
5. 새 값을 입력하면 `metadata.bank_account`에 포함하여 스터디·동아리 모두 새 값으로 교체한다.
6. 기존 계좌번호를 회원 응답에 노출하지 않으며 API 권한 정책은 변경하지 않는다.
7. DB 스키마와 Alembic 마이그레이션은 변경하지 않는다.

## 데이터 흐름

### 뒤로가기

`목록 상태 → router.push(상세) → 상세 < → router.back() → 동일 목록 인스턴스`

직접 진입은 복원할 목록 인스턴스가 없으므로 `fromBoardId` 또는 `boardParentRoute`를 안전한 대체 경로로 사용한다.

### 계좌 수정

- 빈 입력: 프론트가 `bank_account`를 보내지 않음 → `_metadata_for_update`가 기존 저장값 병합
- 새 입력: 프론트가 `bank_account`를 보냄 → 백엔드가 새 값 저장
- 조회: 일반 회원 응답의 `_safe_metadata`는 계속 계좌번호 제거

## 오류 및 보안

- 유효하지 않은 `fromBoardId`는 무시하고 제품 상위 경로로 복귀한다.
- 작성자가 아닌 회원의 수정 권한은 기존 API의 `403 FORBIDDEN` 정책을 유지한다.
- 관리자의 민감 metadata 조회 정책은 변경하지 않는다.
- 기존 계좌를 비우는 기능은 이번 범위에 포함하지 않는다. 빈 입력은 삭제가 아니라 유지 의미다.
- 운영 게시글을 수정하는 브라우저 검증은 실제 저장 없이 입력 가능 상태까지만 확인한다.

## 테스트 전략

### 자동 테스트

- 탐색 기록이 있으면 공지·커뮤니티·참여활동·활동 인증 모두 `back`을 선택한다.
- 탐색 기록이 없고 `fromBoardId`가 있으면 해당 게시판 목록을 대체 경로로 선택한다.
- 직접 진입에 게시판 ID가 없으면 기존 제품 상위 경로를 사용한다.
- 활동 인증 작성에서는 계좌번호가 필수이고 수정에서는 선택 입력이다.
- 수정에서 빈 계좌 입력은 `bank_account`를 추가하지 않으며 기존 서버 값 보존 계약과 호환된다.
- 수정에서 새 계좌 입력은 metadata에 포함된다.
- 백엔드 테스트는 계좌 키 생략 시 보존과 명시 시 교체를 모두 검증한다.

### 수동 회귀

- 동아리 활동 인증, 스터디 활동 인증, 스터디 모집, 공지사항 및 커뮤니티 목록에서 각각 필터·스크롤 상태를 만든 뒤 상세 진입과 복귀를 확인한다.
- 스터디·동아리 활동 인증 수정 화면에서 계좌 입력이 가능하고 기존 값이 노출되지 않는지 확인한다.
- 계좌 입력 없이 저장할 때 기존 값이 유지되고, 새 값을 입력할 때만 변경되는지는 로컬 QA 데이터로 검증한다.

## 범위 제외

- 목록 상태를 영구 저장하거나 앱 재실행 뒤 복원하는 기능
- 기존 계좌번호 표시 또는 마스킹 조회
- 계좌번호 삭제 기능
- 운영 데이터 직접 수정
