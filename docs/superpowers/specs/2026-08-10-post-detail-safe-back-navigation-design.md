# 게시글 상세 안전 뒤로가기 설계

## 목표

공지사항을 포함한 게시글 상세의 뒤로가기가 실제 이전 화면을 우선 사용하고, 이전 기록이 없어도 관리자 화면이나 전체 게시판 모음으로 이동하지 않도록 한다.

## 이동 규칙

1. 라우터에 이전 기록이 있으면 헤더 `<`와 Android 하드웨어 뒤로가기 모두 `router.back()`을 실행한다.
2. 이전 기록이 없으면 게시글이 속한 게시판의 사용자용 상위 허브로 이동한다.
   - 공지: `/(tabs)/notices`
   - 자료공유·행사 사진첩: `/(tabs)/community`
   - 스터디·동아리·네트워킹·활동 인증: `/(tabs)/participation`
   - 건의사항·상조회·원우회: `/(tabs)/council`
   - 그 외: `/(tabs)/home`
3. fallback 경로에는 `/admin`, `/(tabs)/boards`, 게시판 ID 기반 전체/관리 목록을 사용하지 않는다.

## 구현 범위

- 기존 `boardParentRoute`를 게시글 상세의 no-history fallback에 재사용한다.
- `fromBoardId`는 특정 게시판 목록에서 진입한 상세 URL 호환을 위해 유지하지만, 이전 기록이 있느냐를 판단하는 조건으로 사용하지 않는다.
- 게시글 조회, 권한, 데이터 모델은 변경하지 않는다.

## 검증

- 출처 파라미터가 없어도 이전 기록이 있으면 `back`을 선택하는 테스트를 추가한다.
- 이전 기록이 없는 공지 상세가 공지사항 탭으로 fallback하는 테스트를 추가한다.
- 모든 fallback이 관리자 및 전체 게시판 모음 경로가 아닌 사용자 허브인지 확인한다.
- 헤더와 Android 하드웨어 뒤로가기가 같은 핸들러를 사용하는 기존 계약을 유지한다.
