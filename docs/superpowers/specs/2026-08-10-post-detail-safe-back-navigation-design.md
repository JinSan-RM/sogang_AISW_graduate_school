# 게시글 상세 안전 뒤로가기 설계

## 목표

게시글 상세의 뒤로가기가 사용자용 상위 화면으로 안전하게 이동하고, 커뮤니티·참여활동에서 독립 게시판 목록과 탭 내장 목록이 연속으로 나타나는 중복 깊이를 제거한다.

## 이동 규칙

1. 커뮤니티·참여활동 게시글 상세는 헤더 `<`와 Android 하드웨어 뒤로가기에서 게시판의 사용자용 상위 탭으로 `replace`한다. 두 탭은 게시판 목록을 직접 내장하므로 독립 `/board/[boardId]` 목록을 중간 단계로 다시 노출하지 않는다.
2. 그 밖의 게시글 상세는 라우터에 실제 이전 기록이 있으면 `router.back()`을 실행한다.
3. 이전 기록이 없으면 게시글이 속한 게시판의 사용자용 상위 허브로 이동한다.
   - 공지: `/(tabs)/notices`
   - 자료공유·행사 사진첩: `/(tabs)/community`
   - 스터디·동아리·네트워킹·활동 인증: `/(tabs)/participation`
   - 건의사항·상조회·원우회: `/(tabs)/council`
   - 그 외: `/(tabs)/home`
4. fallback 경로에는 `/admin`, `/(tabs)/boards`, 게시판 ID 기반 전체/관리 목록을 사용하지 않는다.

## 구현 범위

- 기존 `boardParentRoute`를 게시글 상세의 상위 탭 판정과 no-history fallback에 재사용한다.
- `fromBoardId`는 특정 게시판 목록에서 진입한 상세 URL 호환을 위해 유지하지만, 뒤로가기 동작을 결정하는 조건으로 사용하지 않는다.
- 커뮤니티·참여활동의 목록 스크롤 위치보다 중복 화면 제거를 우선한다. 상위 탭으로 돌아오면 해당 탭의 기본 목록 상태를 사용한다.
- 게시글 조회, 권한, 데이터 모델은 변경하지 않는다.

## 검증

- 커뮤니티·참여활동 상세는 `fromBoardId`와 이전 기록 유무에 관계없이 각 상위 탭으로 `replace`하는 테스트를 추가한다.
- 그 밖의 상세는 출처 파라미터가 없어도 이전 기록이 있으면 `back`을 선택하는 테스트를 추가한다.
- 이전 기록이 없는 공지 상세가 공지사항 탭으로 fallback하는 테스트를 추가한다.
- 모든 fallback이 관리자 및 전체 게시판 모음 경로가 아닌 사용자 허브인지 확인한다.
- 헤더와 Android 하드웨어 뒤로가기가 같은 핸들러를 사용하는 기존 계약을 유지한다.
