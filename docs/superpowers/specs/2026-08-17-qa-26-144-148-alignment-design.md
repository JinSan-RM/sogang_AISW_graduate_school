# QA 26·144~148·153·161 동아리 선택, 날짜, 마이페이지 및 새로고침 정합화 설계

## 목적

QA 26과 144~148의 확정 요구를 기존 데이터와 화면 상태를 보존하는 방식으로 반영한다.

- 기존 동아리 안내 글은 목록과 상세에서 그대로 유지한다.
- 새 동아리 활동 인증 작성 시 선택 가능한 동아리는 현재 운영 중인 7개로 제한한다.
- 상호부조 행사일은 Asia/Seoul 기준 오늘부터 선택할 수 있다.
- 프로필 수정, 알림 설정, 계정 설정에서 뒤로가면 진입 전 탭을 유지한 채 마이페이지 창을 다시 연다.
- 프로필 이미지가 없으면 닉네임 글자 대신 기본 프로필 아이콘을 표시하고, 이미지가 있으면 해당 이미지를 표시한다.
- 강의후기 스크랩에는 익명 작성자 대체 문구 없이 날짜만 표시한다.
- 주기적 데이터·이미지 주소 갱신으로 화면이 깜빡이지 않도록 하고 사용자가 아래로 당겨 화면 데이터를 갱신하게 한다.

이번 변경은 Phase 3/4의 P0 QA 보정 범위다. DB 스키마, Alembic 마이그레이션 및 기존 게시글 데이터는 변경하지 않는다.

## 확인된 현재 동작과 원인

### QA 26: 동아리 활동 인증 선택 목록

활동 인증 작성 화면은 게시된 `club-promo` 글을 최대 50개까지 그대로 선택 목록에 표시한다. 따라서 현재 운영 중인 7개 동아리뿐 아니라 과거 동아리 안내 글도 함께 노출된다. 과거 글을 숨기거나 삭제하면 기존 안내 목록과 상세까지 영향을 받으므로 선택 화면에서만 현재 동아리를 판별해야 한다.

현재 운영 동아리의 기준 이름과 순서는 서버의 동아리 정리 도메인 규칙에 이미 존재한다.

1. SG_LLM
2. 알바트로스냅
3. 서강의 봄
4. 서뽈링
5. 서강와인
6. 인간지능투자
7. FC리턴윈

실제 안내 글 제목에는 `(사진)`, `(볼링)` 같은 설명 접미사가 붙을 수 있으므로 완전 일치만 사용하면 정상 글이 누락될 수 있다.

### QA 144: 상호부조 날짜 하한

프론트엔드와 백엔드가 모두 상호부조 날짜의 최소값을 KST 오늘에서 2일 뒤로 계산하고, 테스트와 `PLAN.md`도 D+2 정책을 고정한다. 확정된 새 요구는 오늘부터 선택 가능이다. 프론트만 바꾸면 API가 오늘 날짜를 거절하므로 양쪽 정책과 문서를 함께 수정해야 한다.

### QA 145~147: 설정 화면 뒤로가기

마이페이지 드로어에서 프로필 수정, 알림 설정, 계정 설정으로 이동할 때 드로어를 닫고 스택 화면을 연다. 각 화면의 뒤로가기는 일반 `router.back()`만 실행하므로 이전 탭은 보이지만 마이페이지 드로어는 다시 열리지 않는다. 세 화면이 독립적으로 복귀 처리를 구현하면 동작이 다시 달라질 수 있다.

### QA 148: 프로필 이미지 표시

마이페이지 드로어는 이미 업로드 이미지 또는 기본 프로필 아이콘을 올바르게 구분한다. 반면 설정 허브의 프로필 영역은 이미지가 없을 때 닉네임 첫 글자를 아바타 내부에 표시한다. 같은 사용자에게 진입 위치별로 다른 기본 프로필이 보이는 상태다.

### QA 153: 강의후기 스크랩 작성자 표시

내 활동의 스크랩 카드는 모든 게시글에서 `기수 + 작성자 · 날짜` 형식의 메타 정보를 만든다. 강의후기처럼 API가 작성자를 익명 처리하는 게시글도 같은 형식을 사용해 `Anonymous · 날짜`가 표시된다. API가 익명성을 보장하기 위해 사용하는 대체값은 유지하되, 사용자 화면에서는 익명 작성자 대체 문구를 메타 정보로 노출하지 않아야 한다.

### QA 161: 자동 새로고침과 화면 깜빡임

화면 데이터에 영향을 주는 주기 갱신은 홈 알림 배지의 1분 폴링과 보호 이미지 접근 URL의 4분 갱신이다. 후자는 새 서명 URL을 이미지 source로 다시 전달하므로 사진이 다시 로드되며 깜빡일 수 있다. 반면 홈, 공지 및 공통 게시판 목록은 사용자가 직접 당겨서 갱신하는 동작이 일관되게 제공되지 않는다.

알림 수신을 담당하는 전역 백그라운드 처리와 만료된 이미지의 오류 시 재요청은 콘텐츠 화면의 주기적 재렌더링과 목적이 다르므로 유지한다.

## 검토한 접근

### 1. 기존 데이터는 보존하고 공통 UI 규칙으로 필요한 화면만 보정 — 채택

- 동아리 선택 목록에서 공식 이름을 정규화해 현재 7개에 해당하는 최신 게시 글만 골라 공식 순서로 표시한다.
- KST 날짜 하한을 프론트와 API에서 모두 오늘로 통일한다.
- 마이페이지 드로어 Provider에 공통 복귀 동작을 추가해 기존 탭으로 돌아간 직후 드로어를 연다.
- 설정 허브와 드로어가 같은 공통 프로필 아바타 컴포넌트를 사용한다.
- 스크랩 메타 표시를 순수 함수로 분리해 익명 강의후기는 날짜만 반환한다.
- 화면 데이터와 이미지 URL의 주기 갱신을 제거하고 주요 목록에 공통 pull-to-refresh 상태를 연결한다.

기존 데이터 수정 없이 요구 범위를 충족하며, 화면별 중복을 줄일 수 있다.

### 2. 현재 동아리 여부를 DB metadata로 표시 — 미채택

명시적인 운영 상태를 저장할 수 있지만 운영 DB의 7개 글을 별도로 갱신해야 하고 관리자 유지 규칙과 API 필터까지 추가해야 한다. 이번 요구는 기존 글을 보존하면서 선택 UI만 제한하는 것이므로 범위가 과도하다.

### 3. 각 화면에 개별 조건과 뒤로가기를 하드코딩 — 미채택

변경량은 작지만 공식 동아리 목록, 아바타 분기 및 뒤로가기 타이밍이 여러 파일에 중복된다. 한 화면만 수정되거나 제목 접미사가 달라질 때 회귀할 가능성이 높다.

### 4. 이미지 URL을 계속 선제 갱신하되 같은 이미지를 미리 로드해서 교체 — 미채택

만료 전 접근성을 유지할 수 있지만 플랫폼별 이미지 캐시와 선로딩 완료 시점을 별도로 관리해야 한다. 현재 이미지 컴포넌트에는 로드 오류 시 새 접근 URL을 받는 복구 경로가 이미 있으므로, 주기적 source 교체보다 오류 시 복구가 단순하고 화면 깜빡임도 방지한다.

### 5. React Query의 모든 자동 동작과 알림 폴링을 전역 비활성화 — 미채택

화면 갱신은 줄지만 푸시를 사용할 수 없는 웹 환경의 새 알림 감지와 인증·뮤테이션 후 캐시 무효화까지 손상될 수 있다. 사용자에게 보이는 주기적 콘텐츠 교체만 제거하고 기능 유지에 필요한 백그라운드 동작은 남긴다.

## 확정 동작

### QA 26: 현재 동아리만 선택

1. `club-promo` 목록과 상세 API, 과거 안내 게시글 및 과거 활동 인증 연결은 변경하지 않는다.
2. 새 동아리 활동 인증 작성 화면의 선택창에만 현재 7개 동아리를 표시한다.
3. 제목은 공백을 정리한 뒤 공식 이름으로 시작하고, 다음 문자가 문자열 끝·공백·여는 괄호인 경우 해당 동아리 안내 글로 판정한다. `서강의 봄(등산)`과 `서강의 봄 (등산)`은 모두 허용하되 이름 일부가 우연히 같은 제목은 제외한다.
4. 동일 공식 이름에 게시 글이 여러 개면 API의 최신순 결과 중 첫 번째 글 하나만 사용한다.
5. 선택 목록은 서버 반환 순서가 아니라 확정된 공식 7개 순서로 표시한다.
6. 현재 안내 글이 없거나 비공개 상태인 동아리는 선택창에 표시하지 않는다. 과거 글을 대체 항목으로 되살리지 않는다.
7. 스터디 및 네트워킹 활동 인증의 원본 글 선택 동작은 변경하지 않는다.

### QA 144: 오늘부터 날짜 선택

1. KST 오늘은 선택 및 저장할 수 있다.
2. KST 오늘 이전 날짜는 프론트 캘린더에서 선택할 수 없고 API도 거절한다.
3. 내일 이후 날짜에는 최대 선택 기한을 새로 두지 않는다.
4. 기존 과거 글을 다른 필드만 수정할 때 저장된 과거 날짜를 강제로 변경하도록 요구하지 않는 현재 수정 호환 규칙은 유지한다.
5. 기존 D+2 결정을 설명하는 `PLAN.md`와 관련 문서를 오늘 하한으로 갱신한다.

### QA 145~147: 마이페이지 복귀

1. 마이페이지 드로어를 열기 전 사용자가 보고 있던 탭과 그 탭의 상태는 그대로 유지한다.
2. 프로필 수정, 알림 설정, 계정 설정의 헤더 `<`를 누르면 해당 설정 화면을 닫고 기존 탭 위에 마이페이지 드로어를 다시 연다.
3. Android 하드웨어 뒤로가기도 같은 공통 복귀 함수를 사용한다.
4. 일반적인 진입에서는 `router.back()`으로 기존 탭 인스턴스를 활성화해 탭, 필터 및 스크롤 상태를 보존한다.
5. 탐색 기록이 없는 직접 링크 진입에서는 안전한 기본 탭으로 이동한 뒤 마이페이지 드로어를 연다.
6. 저장 성공 뒤 화면을 떠나는 기존 동작은 별도 요구가 없는 한 유지하고, 이번 범위는 사용자의 명시적 뒤로가기에 적용한다.

### QA 148: 프로필 표시

1. 유효한 프로필 이미지가 있으면 설정 허브와 마이페이지 드로어 모두 같은 이미지를 표시한다.
2. 이미지가 없으면 두 위치 모두 기존 기본 프로필 아이콘을 표시한다.
3. 아바타 내부에는 닉네임 첫 글자, `?` 또는 기타 문자 대체값을 표시하지 않는다.
4. 아바타 옆의 사용자 닉네임·기수 등 기존 프로필 텍스트는 유지한다. 이번 요구의 `닉네임 안뜨게`는 기본 아바타 내부의 닉네임 글자를 제거하는 의미로 적용한다.
5. 업로드·삭제 뒤 기존 사용자 조회 캐시 갱신 규칙을 사용해 이미지와 기본 아이콘이 즉시 전환되도록 한다.

### QA 153: 강의후기 스크랩은 날짜만 표시

1. 강의후기 스크랩 카드의 메타 영역에는 게시글 작성 날짜만 표시한다.
2. `Anonymous`, 기수, 구분점은 표시하지 않는다.
3. 일반 실명 게시글 스크랩은 기존 `기수 + 작성자 · 날짜` 형식을 유지한다.
4. 익명성에 관한 API 응답과 관리자 권한 정책은 변경하지 않는다.
5. 내가 쓴 글 및 댓글 단 글 카드의 기존 메타 표시는 변경하지 않는다.

### QA 161: 당겨서 새로고침

1. 홈 알림 배지 쿼리의 1분 화면 폴링을 제거한다.
2. 보호 이미지 접근 URL의 4분 주기 갱신을 제거하여 같은 화면에 머무는 동안 이미지 source를 선제 교체하지 않는다.
3. 보호 이미지 URL이 실제로 만료되거나 로드에 실패하면 기존 이미지 오류 콜백이 새 접근 URL을 요청해 자동 복구한다.
4. 전역 알림 수신·웹 폴링은 유지하며 새 알림이 있을 때만 사용자 알림 UI를 표시한다.
5. 홈을 아래로 당기면 게시판 구성, 배너, 공지, 일정, 사진첩 및 알림 배지를 한 번에 다시 조회한다.
6. 공지 탭을 아래로 당기면 공지 게시판과 현재 필터의 게시글을 함께 다시 조회한다.
7. 공통 게시판 목록을 아래로 당기면 현재 게시판·탭·필터·검색어·정렬을 유지한 채 첫 페이지부터 다시 조회한다. 동아리·스터디·네트워킹, 커뮤니티 및 원우회 목록도 이 공통 동작을 사용한다.
8. 일정 목록, 알림 목록 및 내 활동처럼 이미 pull-to-refresh가 있는 화면은 기존 동작을 유지한다.
9. 새로고침 중에는 해당 스크롤의 네이티브 refresh indicator만 표시하고 전체 화면 로딩 상태로 되돌리지 않는다.

## 구조 및 데이터 흐름

### 동아리 선택

`게시된 club-promo 조회 → 공식 이름 경계 규칙으로 분류 → 이름별 최신 글 1개 선택 → 공식 순서 정렬 → 선택 바텀시트`

필터는 순수 함수로 분리하여 운영 데이터 없이도 제목 변형, 중복 및 과거 글 제외를 테스트할 수 있게 한다.

### 날짜

`KST 오늘 계산 → 프론트 최소 선택일 → 제출 → API KST 오늘 재검증`

클라이언트 날짜나 UTC 날짜가 자정 부근에 달라져도 서버의 Asia/Seoul 달력 날짜가 최종 기준이다.

### 마이페이지 복귀

`기존 탭 위 드로어 → 설정 화면 push → 명시적 뒤로가기 → 기존 탭 back/안전 경로 → 같은 Provider가 드로어 open`

드로어 재개방은 Provider의 공통 함수가 담당하며 세 설정 화면은 동일한 훅을 사용한다.

### 프로필 아바타

`현재 사용자 응답 → 유효한 이미지 식별자/URL 확인 → 공통 아바타 → 이미지 또는 DefaultAvatarIcon`

### 스크랩 메타

`스크랩 항목 → 강의후기 여부 판정 → 날짜만 또는 작성자 + 날짜`

작성자 정보 제거는 표시 단계에서만 수행하므로 API의 익명 응답 계약을 약화시키지 않는다.

### 새로고침

`사용자 pull gesture → 현재 화면의 관련 query refetch 병렬 실행 → 기존 콘텐츠 유지 → refresh indicator 종료`

보호 이미지는 `기존 서명 URL 유지 → 로드 오류 발생 → access URL 재요청 → image source 교체` 순서로 복구한다.

## 오류 및 경계 처리

- 현재 동아리 안내 글 조회가 실패하면 기존 오류·재시도 UX를 유지하며 과거 글 전체를 대신 노출하지 않는다.
- 공식 이름과 일치하는 안내 글이 하나도 없으면 빈 선택 상태를 표시한다.
- 설정 화면에서 빠르게 뒤로가기를 여러 번 눌러도 중복 라우팅이나 드로어 애니메이션이 쌓이지 않도록 공통 복귀 동작에 재진입 방지를 둔다.
- 프로필 이미지 값이 비어 있거나 유효하지 않으면 기본 아이콘으로 안전하게 대체한다.
- API는 과거 날짜에 기존과 같은 정규화된 오류 응답을 반환한다.
- 동시에 여러 홈 쿼리를 갱신할 때 일부 요청이 실패해도 기존에 성공적으로 표시한 다른 섹션의 데이터를 비우지 않는다.
- pull gesture 연속 입력 중에는 새로고침 상태를 하나로 묶어 불필요한 중복 요청을 만들지 않는다.
- 이미지 접근 URL 재발급이 실패하면 빈 화면으로 전환하지 않고 해당 이미지 컴포넌트의 기존 오류·자리표시자 처리를 유지한다.

## 테스트 전략

### 자동 테스트

- 공식 7개 제목과 괄호 접미사를 인식하고 공식 순서로 반환한다.
- 이름이 유사한 과거 글과 현재 목록에 없는 동아리 글을 제외한다.
- 같은 공식 동아리 글이 여러 개면 최신 결과 하나만 선택한다.
- 상호부조 생성/변경에서 KST 오늘을 허용하고 어제를 거절한다.
- 프론트 최소 날짜가 KST 오늘이며 기존 D+2 단언이 남아 있지 않다.
- 프로필·알림·계정 설정의 헤더 뒤로가기와 Android 뒤로가기가 공통 마이페이지 복귀 동작을 사용한다.
- 프로필 이미지가 있으면 이미지, 없으면 기본 아이콘을 선택하고 닉네임 첫 글자를 아바타에 렌더링하지 않는다.
- 강의후기 스크랩은 날짜만 반환하고 다른 일반 스크랩은 기존 작성자·날짜 형식을 유지한다.
- 홈 알림 배지 및 미디어 접근 URL 쿼리에 주기 갱신 옵션이 남아 있지 않다.
- 홈·공지·공통 게시판 목록의 pull-to-refresh가 현재 쿼리들을 호출하고, 재조회 중 기존 콘텐츠를 유지한다.
- 이미지 로드 오류 시 접근 URL 재요청 경로와 전역 알림 수신 폴링은 유지된다.
- 기존 전체 프론트엔드 및 관련 백엔드 테스트를 실행한다.

### 수동 회귀

- 동아리 안내 목록과 예전 글 상세가 그대로 열리는지 확인한다.
- 새 동아리 활동 인증 선택창에 현재 7개만 공식 순서로 표시되는지 확인한다.
- KST 오늘, 어제, 내일을 각각 선택·제출해 경계를 확인한다.
- 홈·공지·커뮤니티·참여활동 등 서로 다른 탭에서 마이페이지를 연 뒤 세 설정 화면에 진입하고, 헤더 및 Android 뒤로가기로 원래 탭 위의 마이페이지가 다시 뜨는지 확인한다.
- 프로필 이미지 업로드 전·후·삭제 후 설정 허브와 드로어 표시가 동일한지 확인한다.
- 강의후기를 스크랩한 뒤 내 활동에서 `Anonymous` 없이 날짜만 보이는지 확인한다.
- 홈, 공지 및 각 주요 게시판을 5분 이상 열어 두어 주기적인 전체 화면·이미지 깜빡임이 없는지 확인한다.
- 같은 화면들을 아래로 당겨 최신 데이터와 알림 배지가 갱신되고 전체 로딩 화면으로 바뀌지 않는지 확인한다.
- 만료된 보호 이미지 URL을 재현해 이미지 오류 후 새 URL로 복구되는지 확인한다.
