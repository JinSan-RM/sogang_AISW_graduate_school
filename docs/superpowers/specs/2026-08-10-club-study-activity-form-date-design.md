# Activity Certification Form Labels and Date Limit Design

## Goal

참여활동의 동아리·스터디·네트워킹 활동인증 등록 및 수정 화면에서 사진 영역과 활동 소감 입력란을 기존 값이 채워진 상태에서도 명확히 구분한다. 세 활동인증 화면에서는 과거 날짜부터 한국시간 기준 오늘까지만 활동일로 선택할 수 있게 하고, 미래 날짜는 달력과 저장 단계 모두에서 거부한다.

## Approved scope

- 대상 게시판은 `club-activity`, `study-activity`, `networking-activity`이다.
- 세 게시판의 등록·수정 화면에 같은 사진·소감 구분 표현을 적용한다.
- 세 게시판의 활동일은 과거 날짜와 오늘만 허용한다.
- 상조회 등 활동인증이 아닌 다른 달력 사용 화면의 날짜 정책은 변경하지 않는다.
- 상부 소속 그룹 선택, 계좌, 참가자, 첨부파일 저장 방식은 변경하지 않는다.

## Form presentation

활동인증 전용 폼의 사진 선택 영역 위에 `활동 사진`, 소감 입력 영역 위에 `활동 소감` 고정 라벨을 표시한다. 라벨은 플레이스홀더와 별개이므로 사진이 선택되거나 소감 값이 채워진 수정 화면에서도 각 영역의 용도가 사라지지 않는다.

두 영역은 기존 디자인 토큰과 활동인증 폼의 여백을 사용해 시각적으로 분리한다. 사진 미리보기, 사진 추가·삭제, 소감 입력 동작은 유지하고 별도의 카드나 신규 입력 모델은 만들지 않는다.

## Date policy

동아리·스터디·네트워킹 활동인증의 최대 선택 날짜는 폼을 보는 시점의 `Asia/Seoul` 오늘이다. 최소 날짜는 두지 않는다.

- 오늘 이전의 모든 날짜는 선택할 수 있다.
- 오늘은 선택할 수 있다.
- 내일부터의 날짜 셀은 비활성화하며 눌러도 선택값이 바뀌지 않는다.
- 현재 달 이후로 넘어가는 달력의 다음 버튼은 비활성화한다.
- 자정이 지난 채 폼을 오래 열어 둔 경우를 고려해 제출 시점에 한국시간 오늘을 다시 계산한다.
- 기존 데이터에 미래 활동일이 저장되어 있다면 수정 화면에서 안내 오류를 보여 주고, 오늘 또는 과거 날짜로 고치기 전에는 저장하지 않는다.

## Implementation shape

### Shared calendar

공용 `InlineCalendar`에 선택 가능한 최대 날짜를 전달하는 선택적 속성을 추가한다. 최대 날짜가 없는 기존 호출은 지금과 동일하게 동작한다. 날짜 셀의 비활성 여부는 기존 최소 날짜와 새 최대 날짜를 함께 평가하고, 월 이동 버튼도 최대 월을 넘지 않게 한다.

### Board-scoped application

활동인증 폼은 게시판 유형이 `activity_certification`일 때만 최대 날짜를 달력에 전달한다. 이를 통해 세 활동인증 게시판에는 같은 정책을 적용하고, 상조회 등 다른 달력 화면의 정책은 바꾸지 않는다.

### Time-zone-safe validation

날짜 유틸리티는 `Asia/Seoul` 달력 날짜를 기준으로 오늘의 날짜 키를 만든다. 문자열 비교 전에 지원 형식의 유효성을 확인하고, 동아리·스터디·네트워킹 활동인증 제출 시 활동일이 오늘보다 미래이면 필드 오류와 `오늘 이후 날짜는 선택할 수 없어요.` 안내를 표시한다.

UI 비활성화와 제출 검증은 같은 날짜 판정 함수를 사용해 서로 다른 경계값을 만들지 않는다.

## Error and accessibility behavior

- 비활성 날짜는 기존 달력의 비활성 색상과 접근성 상태를 사용한다.
- 최대 월에 도달하면 다음 달 버튼도 비활성 상태가 시각적·접근성 속성으로 전달된다.
- 미래 날짜 셀을 눌렀을 때 달력을 닫거나 기존 선택값을 지우지 않는다.
- 제출 검증 실패 시 네트워크 요청을 보내지 않고 활동일 입력 위치에 수정 가능한 안내를 보여 준다.
- 날짜가 비어 있거나 형식이 잘못된 경우에는 기존 필수 입력 검증을 유지한다.

## Alternatives considered

1. **공용 달력에 선택적 최대 날짜를 추가하고 세 활동인증 게시판에서만 사용한다.** 비활성 표시와 저장 검증을 함께 제공하면서 다른 화면의 날짜 정책을 보존하므로 이 방식을 선택한다.
2. 달력은 그대로 두고 제출할 때만 미래 날짜를 거부한다. 사용자가 선택한 뒤에야 실패를 알게 되어 “미래 날짜는 클릭되지 않도록”이라는 요구를 충족하지 못한다.
3. 활동인증 화면 안에 별도 달력 컴포넌트를 복제한다. 초기 구현은 단순하지만 공용 달력의 디자인·접근성 수정이 분산되고 날짜 경계 로직이 중복된다.

## Verification

- 날짜 유틸 테스트에서 한국시간 기준 어제, 오늘, 내일의 허용 여부를 검증한다.
- UTC 날짜가 한국 날짜와 다른 경계 시각에서도 오늘 판정이 안정적인지 검증한다.
- 달력 테스트 또는 순수 판정 테스트에서 최대 날짜 이후 셀이 비활성화되는지 검증한다.
- 동아리·스터디·네트워킹 활동인증 제출은 미래 날짜에서 차단되고 과거·오늘 날짜에서 통과하는지 검증한다.
- 상조회처럼 기존 최소 날짜 정책을 사용하는 다른 화면의 동작이 유지되는지 회귀 검증한다.
- 수정 화면에서 첨부 사진과 소감 값이 이미 채워져 있어도 `활동 사진`, `활동 소감` 라벨이 항상 표시되는지 확인한다.
- 프론트엔드 집중 테스트, 전체 테스트, 타입 검사, 린트와 웹 export를 실행한다.
