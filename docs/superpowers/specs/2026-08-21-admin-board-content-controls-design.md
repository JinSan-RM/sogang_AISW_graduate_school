# Unified Admin Board Management Design

## Status

Approved in conversation on 2026-08-21. This design replaces the earlier split between `게시판`, `전체 게시글`, and board-specific admin menu items.

## Goal

관리자가 하나의 `게시판 관리` 메뉴에서 공지사항, 커뮤니티·자료, 참여활동, 원우회의 모든 게시판을 찾고 다음 작업을 수행할 수 있게 한다.

- 게시판별 콘텐츠 관리
- 게시판 이름, 설명, 노출, 정렬과 권한 관리
- 공지, 건의사항, 상조회, 원우회 소개처럼 게시판 성격에 따른 전용 관리
- 동아리와 네트워킹 안내 게시글의 대표 이미지 관리

기존 관리자 기능과 API를 재사용하며, 같은 기능을 여러 화면에 복제하지 않는다.

## Current problem

현재 관리자 화면은 게시판 구조 설정, 전체 게시글 관리, 공지사항, 건의사항, 상조회, FAQ, 일정과 원우회 소개 관리가 서로 다른 사이드 메뉴에 나뉘어 있다. 데이터와 API는 대체로 공유하지만 관리자는 동일한 게시판을 설정할 때 여러 메뉴를 오가야 한다.

현재 초안 PR의 그룹 탭은 게시글을 찾기 쉽게 만들지만 기존 전용 메뉴로 이동하는 바로가기를 추가하는 방식이라 진입 경로 중복은 남는다. 통합 화면은 이 바로가기를 최종 구조로 사용하지 않고 기존 전용 편집기를 선택한 게시판의 패널로 배치한다.

## Scope

### Included

- 기존 `게시판`, `전체 게시글`, `공지사항`, `건의사항`, `상조회`, `임원진`, `기장단`, `역대 원우회`, `FAQ`, `일정` 관리 진입점을 하나의 `게시판 관리` 메뉴로 통합한다.
- 모든 등록 게시판을 콘텐츠 그룹과 실제 게시판의 두 단계로 탐색한다.
- 선택한 게시판에 `콘텐츠`와 `운영 설정` 탭을 제공하고, 게시판별 전용 편집기는 `콘텐츠` 탭 자체로 사용한다.
- 기존 작성, 수정, 고정, 삭제, 답변, 상태 처리, 메타데이터 편집과 이미지 업로드 동작을 보존한다.
- 대시보드의 기존 빠른 관리 카드는 통합 화면의 해당 그룹과 게시판을 미리 선택해 연다.

### Not included

- 사용자 앱의 메뉴나 게시판 화면 재설계
- 새 게시판 유형, 새 권한 체계 또는 새 저장소 도입
- 강의후기와 시험족보의 개인정보 관련 정책을 관리자 선택값으로 변경
- Alembic 마이그레이션, DB 스키마 변경, seed 변경 또는 수동 SQL 작업
- 배너, 회원, 원우회비 납부자, 신고와 계정 승인처럼 특정 게시판에 속하지 않는 관리자 기능 통합

## Information architecture

관리자 사이드 메뉴에는 `게시판 관리`를 한 번만 표시한다. 통합 화면은 항상 같은 세 단계로 동작한다.

1. 콘텐츠 그룹 선택
2. 실제 게시판 선택
3. 선택한 게시판의 관리 탭 선택

```text
게시판 관리
└─ 전체 / 공지사항 / 커뮤니티·자료 / 참여활동 / 원우회
   └─ 게시판 선택
      ├─ 콘텐츠 (게시판별 전용 워크플로 포함)
      └─ 운영 설정
```

`전체` 그룹에도 게시판 선택 목록을 제공한다. 기본값인 `모든 게시판`은 기존 전체 검색, 상태 필터와 공통 게시글 조작을 유지한다. `모든 게시판`에서는 단일 대상이 없으므로 `운영 설정`을 표시하지 않는다. 실제 게시판을 선택하면 다른 그룹과 같은 관리 탭을 제공한다.

그룹이나 게시판을 바꾸면 선택할 수 없는 이전 탭을 유지하지 않고 해당 게시판의 첫 번째 유효 탭인 `콘텐츠`로 이동한다. 화면은 선택한 게시판 ID를 단일 기준 상태로 사용하며, 콘텐츠 그룹은 게시판 검색 범위만 제한한다.

## Group and board mapping

그룹은 표시용 이름을 하드코딩한 게시판 목록이 아니라 서버에서 받은 `category`, `sort_order`, `id`를 기준으로 구성한다. 현재 등록된 게시판은 다음과 같이 나타난다.

### 공지사항

- 전체 공지
- 학사 공지
- 행사 공지
- 웨비나·특강 공지
- 학사 일정

### 커뮤니티·자료

- 사진첩
- 강의후기
- 시험족보
- 종합시험
- 졸업논문
- 전공 커뮤니티
- 논문 자료 공유
- 세미나 공유
- 채용 정보 공유

### 참여활동

- 동아리 활동 인증
- 스터디 활동 인증
- 네트워킹 활동 인증
- 동아리 지원 신청
- 동아리 홍보
- 스터디 모집
- 스터디 지원 신청
- 동문 주소록
- 네트워킹 안내

### 원우회

- 원우회 활동내역
- 회계 장부
- 건의사항
- 상조회
- 임원진 소개
- 기장단 소개
- 역대 원우회
- 건의사항 피드백
- 자주 묻는 질문
- 로드맵·원우회비 혜택

`notices`는 공지사항, `community`와 `resources`는 커뮤니티·자료, `participation`, `club`, `study`, `alumni`는 참여활동, `council`과 `gsa`는 원우회로 묶는다. 새 범주의 게시판이나 분류할 수 없는 게시판은 `전체`에서 관리할 수 있고 임의의 기존 그룹에 잘못 포함하지 않는다.

## Management tabs

### 콘텐츠

게시판 유형에 맞는 기존 콘텐츠 편집기를 표시한다.

- `post`, `resource`: 게시글 검색, 등록, 열기, 수정, 고정과 삭제
- `notice`: 공지 분류, 이미지, 마감일, 상단 고정과 원우회 활동내역 연동
- `album`: 이미지 중심 게시글 목록과 등록
- `activity_certification`: 활동일, 참여자, 활동 사진과 처리 대상 게시글
- `activity_history`: 연동된 공지 기반 원우회 활동내역
- `suggestion`: 접수 상태와 공식 답변
- `mutual_aid`: 관리자 전용 증빙 확인, 완료와 반려
- `calendar`: 기존 일정 목록과 작성, 수정, 삭제
- `external_link`: 현재 외부 링크 확인과 기존 메타데이터 기반 링크 편집
- `organization_intro`: 임원진, 기장단 또는 역대 원우회 전용 편집기
- `faq`: FAQ 목록, 정렬, 활성 상태와 편집
- `guide`: 지원되는 별도 콘텐츠 저장 형식이 없으므로 빈 게시글 목록을 만들지 않고 게시판 이름, 설명, 노출과 권한을 `운영 설정`에서 관리

표준 게시글이 없는 게시판에 빈 게시글 목록을 표시하지 않는다. 각 편집기는 기존 API와 검증 규칙을 그대로 사용한다.

### 운영 설정

기존 게시판 관리 API가 지원하는 필드만 편집한다.

- 이름
- 설명
- 정렬 순서
- 읽기 권한
- 쓰기 권한
- 익명 허용
- 활성·숨김 상태

기존 게시판의 `slug`, `category`, `board_type`은 사용자 라우팅과 서버 정책의 구조 식별자이므로 읽기 전용으로 표시한다. 기존의 새 게시판 등록 기능은 `고급 설정` 진입점으로 보존하며, 새 게시판을 만들 때만 이 구조 필드를 입력할 수 있다.

서버가 강제하는 정책은 일반 설정으로 가장하지 않고 잠금 상태와 이유를 함께 표시한다.

- `lecture-reviews`: 강제 익명, 댓글 불가
- `exam-archive`: 일반 작성자 표시, 댓글 허용
- `suggestion`: 익명 표시와 공식 답변 흐름
- `club-promo`, `networking-programs`: 관리자 작성 전용
- 원우회 게시판의 회원·관리자 작성 제한

잠긴 정책은 이 작업에서 변경하지 않으며 기존 백엔드 검증을 최종 권한 기준으로 유지한다.

게시판별 전용 기능은 별도 메뉴나 중복 탭으로 분리하지 않는다. 동아리·네트워킹 대표 이미지, 공지 연동, 원우회 소개, 외부 링크, 건의사항 답변과 상조회 처리는 모두 해당 게시판의 `콘텐츠` 안에서 관리한다.

## Community controls

커뮤니티·자료 그룹은 다른 그룹과 같은 콘텐츠·운영 설정 구조를 사용하면서 다음 제품 정책을 명확히 보여준다.

- 사진첩은 이미지가 필요한 앨범 작성 규칙을 유지한다.
- 강의후기는 작성자 정보를 노출하지 않고 댓글을 제공하지 않는다.
- 시험족보는 정상 작성자 규칙과 댓글을 유지한다.
- 종합시험과 졸업논문은 기존 문서 첨부, 다운로드와 게시판별 고정 분류를 유지한다.
- 자료 게시글 이동은 기존 자료 게시판 사이에서만 가능하고 게시글 ID, 첨부, 댓글, 좋아요와 북마크를 보존한다.
- 일반 커뮤니티 게시판은 운영 설정의 익명 허용과 읽기·쓰기 권한을 따른다.

작성자·댓글 정책은 관리자 화면에 현재 상태를 표시하지만 이 기능에서 임의로 바꾸지 않는다. 이렇게 해야 시험족보 작성자 표시 QA와 강의후기 익명성 규칙이 다시 깨지지 않는다.

## Component architecture

현재 `frontend/app/admin/index.tsx`에 있는 상태와 편집 UI를 한 번에 다시 구현하지 않는다. 기존 핸들러와 폼을 역할별 패널로 추출하고 통합 셸에서 조합한다.

- `AdminBoardManagement`: 콘텐츠 그룹, 게시판과 관리 탭 선택을 소유하는 셸
- `AdminBoardSelector`: 서버 게시판을 그룹화하고 정렬하는 탐색 컴포넌트
- `AdminBoardContentPanel`: 선택한 게시판 유형에 맞는 기존 콘텐츠 또는 전용 편집기를 렌더링
- `AdminBoardSettingsPanel`: 공통 게시판 설정과 잠긴 정책 안내
- capability registry: `board_type`과 필요한 최소한의 `slug` 예외를 관리 패널과 기능 플래그로 변환하는 순수 함수

통합 셸은 게시판별 세부 폼 값을 직접 해석하지 않는다. 각 패널이 자신의 입력, 검증, 저장과 오류 표시를 책임지고 기존 서비스 함수를 호출한다. capability registry는 UI 선택만 결정하며 권한을 부여하지 않는다.

## Data flow and cache behavior

1. 관리자 권한 확인 후 게시판 목록을 한 번 조회한다.
2. 그룹과 선택한 게시판 ID로 표시 목록과 capability를 계산한다.
3. `콘텐츠` 탭을 열었을 때 해당 게시판 유형에 필요한 쿼리만 활성화한다.
4. `운영 설정` 저장은 기존 관리자 게시판 수정 API를 호출한다.
5. 게시판별 전용 콘텐츠 저장은 기존 게시판 메타데이터, 게시글 수정 또는 미디어 API를 사용한다.
6. 저장 성공 후 `admin-boards`, 사용자 게시판 목록, 해당 콘텐츠 목록과 상세 캐시만 무효화한다.
7. 다른 그룹이나 숨겨진 패널의 전용 쿼리는 비활성 상태로 유지해 중복 호출을 방지한다.

관리자 설정 저장은 기존 `boards` 행과 게시글·메타데이터를 정상적으로 갱신한다. 이는 기존 관리자 기능의 데이터 저장이며, DB 스키마 변경이나 수동 DB 작업을 의미하지 않는다.

## Representative image replacement

동아리와 네트워킹 안내의 대표 이미지는 첨부 이미지 중 정렬 순서가 가장 빠른 이미지다. 관리자 카드에서 이미지 한 장을 선택하면 게시글 상세를 다시 읽고 다음 규칙으로 첨부 순서를 만든다.

1. 기존 첫 번째 이미지가 있으면 같은 위치를 새 이미지로 교체한다.
2. 이미지가 없으면 새 이미지를 첨부 목록 앞에 넣는다.
3. 나머지 이미지와 문서 첨부의 상대 순서는 유지한다.
4. 제목, 본문, 카테고리, 익명 여부, 참여 링크를 포함한 메타데이터와 마감일은 기존 값을 보존한다.
5. 저장 성공 후 관리자 목록, 사용자 게시판 목록과 게시글 상세 캐시를 무효화한다.
6. 파일 선택 취소는 게시글을 변경하지 않는다.
7. 업로드나 저장 실패는 기존 게시글을 유지하고 관리자에게 오류를 알린다.

대표 이미지 교체는 기존 미디어 업로드와 게시글 수정 API를 사용한다.

## Error handling and destructive actions

- 목록 조회 실패는 선택한 패널 안에 재시도 가능한 오류 상태로 표시한다.
- 저장 실패는 입력값을 유지하고 성공 메시지를 표시하지 않는다.
- 게시글, 일정과 FAQ 삭제는 기존 확인 절차를 유지한다.
- 게시판 숨김은 삭제와 구분하고, 기존 콘텐츠를 삭제하지 않는다는 안내를 표시한다.
- 권한 또는 잠긴 정책을 서버가 거절하면 서버 오류를 관리자에게 보여주고 UI 상태를 성공으로 변경하지 않는다.
- 대표 이미지 업로드 후 게시글 저장이 실패하면 기존 대표 이미지는 유지된다. 새 미디어 정리는 기존 업로드 수명주기 정책에 맡긴다.

## Compatibility constraints

- 기존 관리자 API와 백엔드 관리자 권한 검사를 그대로 사용한다.
- 기존 공지, 건의사항, 상조회, 일정, FAQ와 원우회 소개의 입력값 및 저장 형식을 변경하지 않는다.
- 기존 전체 게시글 검색, 상태 필터, 열기, 수정, 고정과 삭제를 유지한다.
- 대시보드 바로가기와 내부 진입 함수는 통합 화면의 그룹·게시판 선택으로 변환한다.
- 현재 작업공간에 남아 있는 일정 한국시간 변환 변경을 보존하고 이 PR에 섞지 않는다.
- 일반 게시판의 첨부 순서, 사용자 화면과 작성자 표시 정책을 변경하지 않는다.
- `club-promo`와 `networking-programs` 외에는 대표 이미지 변경 버튼을 표시하지 않는다.
- 통합 완료 후 제거되는 것은 중복 사이드 메뉴 진입점이며 기존 관리 기능 자체가 아니다.

## Acceptance criteria

- 관리자 사이드 메뉴에는 게시판 관련 통합 진입점이 하나만 있다.
- 공지사항, 커뮤니티·자료, 참여활동과 원우회 모두 동일한 그룹 → 게시판 → 관리 탭 구조를 사용한다.
- 현재 등록된 모든 게시판은 적절한 그룹 또는 `전체`에서 찾을 수 있다.
- 게시판 설정과 게시판별 콘텐츠·전용 기능을 다른 사이드 메뉴로 이동하지 않고 처리할 수 있다.
- 커뮤니티의 작성자와 댓글 정책이 기존 제품 규칙대로 유지된다.
- 기존 관리 기능과 사용자 화면에 회귀가 없다.
- DB 스키마, 마이그레이션과 수동 DB 작업이 없다.
