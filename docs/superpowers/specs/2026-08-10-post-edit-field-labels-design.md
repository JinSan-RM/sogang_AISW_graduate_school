# Post Edit Field Labels Design

## Goal

기존 게시글을 수정할 때 입력값 때문에 placeholder가 보이지 않더라도 제목 입력칸과 내용 입력칸을 즉시 구분할 수 있게 한다.

## Approved behavior

- 게시글 수정 화면의 제목 입력칸 위에는 `제목` 라벨을 항상 표시한다.
- 게시글 수정 화면의 본문 입력칸 위에는 `내용` 라벨을 항상 표시한다.
- 라벨 노출은 게시판 slug나 게시판 조회 성공 여부에 의존하지 않는다.
- 제목과 내용 입력칸의 기존 높이, 테두리, 값, 저장 동작은 유지한다.
- 스터디 모집 상태와 연락수단 등 게시판별 추가 필드는 기존 조건부 동작을 유지한다.
- placeholder는 빈 입력칸을 안내하는 보조 문구로 유지하고 필드 이름 역할을 맡기지 않는다.

## Implementation boundary

변경 범위는 공통 게시글 수정 라우트 `frontend/app/board/post/edit/[postId].tsx`의 제목·내용 라벨 조건을 제거하는 것으로 제한한다. 새 글 등록 화면과 활동인증·상조회 전용 수정 라우팅, API 요청 형식 및 데이터 모델은 변경하지 않는다.

## Alternatives considered

1. **항상 보이는 외부 라벨 — 선택.** 기존 UI 구조를 유지하면서 입력값 유무와 게시판 판별 상태에 관계없이 필드 의미를 전달한다.
2. 플로팅 라벨. 입력 상태에 따라 라벨을 이동시키는 추가 상태와 애니메이션이 필요해 이번 문제에 비해 복잡하다.
3. placeholder 문구만 강화. 수정 화면에서는 기존 값이 placeholder를 가리므로 문제를 해결하지 못한다.

## Verification

- 수정 화면 렌더링 테스트에서 일반 게시판과 스터디 게시판 모두 `제목`, `내용` 라벨을 노출하는지 확인한다.
- 스터디 전용 `모집 상태`, `스터디장 연락수단`은 계속 스터디에서만 노출되는지 확인한다.
- 프론트엔드 전체 테스트, 타입 검사, 린트, 웹 export를 실행한다.
